# StayOnBeat AI 代理协作指南

> 用途：定义 AI 代理在仓库中的工作方式、验收标准和决策记录。
> 优先级：低于 `AGENTS.md`，高于代理的默认行为。

## 1. 角色定位

AI 代理在本仓库承担三类工作：

1. **方案整理**：整理需求、竞品参考、技术选项和风险。
2. **实现**：在文档基线批准后，实现功能并保持与文档一致。
3. **验证**：运行测试、检查行为、报告偏差。

当前仓库处于“方案整理”阶段，尚未批准编码。

## 2. 任务启动清单

开始任何任务前，先确认：

- [ ] 已读 `AGENTS.md`。
- [ ] 已读与本任务相关的产品/技术文档。
- [ ] 已读 `docs/development-plan.md` 的里程碑与任务拆解。
- [ ] 明确“本次只产出文档”还是“可以写代码”。
- [ ] 识别需要修改的文档文件，避免跨领域误改。
- [ ] 如任务会改变架构或评分规则，先记录到决策记录。

## 3. 常见任务模板

### 3.1 新增功能

1. 在 `docs/product-design.md` 补充用户价值、流程、交互、验收指标。
2. 在 `docs/technical-solution.md` 补充模块、数据结构、边界情况、测试策略。
3. 如涉及视觉，补充布局、颜色、动效、可访问性说明。
4. 用户批准后才进入实现。

### 3.2 修改判定/评分

1. 同步修改产品设计“判定与评分 UX”。
2. 同步修改技术方案“匹配度与判定算法”和“数据模型”。
3. 更新测试策略。
4. 在决策记录说明理由。

### 3.3 新增依赖

1. 在技术选型表中写明库、用途、替代方案。
2. 说明包体积、维护风险、是否引入后端能力。
3. 用户确认后再安装。

## 4. 验收清单（未来编码阶段）

功能完成前至少确认：

- [ ] 节拍调度不依赖业务定时器发声。
- [ ] 键盘重复与多输入源重复不会重复计分。
- [ ] 静音模式下视觉节拍清晰可用。
- [ ] 刷新页面后设置可恢复，训练记录可保存。
- [ ] 训练中修改配置不会导致评分错乱。
- [ ] 判定/匹配度有单元测试覆盖。
- [ ] 暗色/亮色主题均可用。
- [ ] 移动端触控点击无 300ms 级明显延迟。
- [ ] 无障碍：可键盘操作、焦点可见、动画可关闭。

## 5. 评审关注点

- 是否改变产品定位或 MVP 范围。
- 是否增加不必要的复杂度。
- 是否复制参考站点素材或文案。
- 是否新增未批准的后端/云服务。
- 是否把计时精度问题掩盖在视觉层。
- 是否导致移动端或静音模式体验劣化。

## 7. 输出要求

AI 代理最终回复应至少说明：

- 完成了什么。
- 修改/新增了哪些文件。
- 是否影响产品、技术或评分规则。
- 哪些内容需要用户确认。
- 下一步建议。

若没有修改文件，直接说明分析结论和下一步即可。
